## 1. 项目概况

| 项 | 内容 |
|---|---|

## 2. 架构分层

```
┌─────────────────────────────────────────────┐
│  视图层  pages/*  +  components/*            │  ← 只认 Article，不认后端字段
├─────────────────────────────────────────────┤
│  组合式 / 状态  useSearch · useAuth(响应式单例)│  ← 刻意不用 Pinia
├─────────────────────────────────────────────┤
│  接口层  api/articles.ts · api/auth.ts       │  ← 业务语义，非 HTTP 细节
├─────────────────────────────────────────────┤
│  防腐层  adapters.ts  (DTO → 视图模型)        │  ← 后端字段变了只改这一处
├─────────────────────────────────────────────┤
│  请求内核  client.ts  (业务码/取消/超时/Cookie) │  ← 统一收敛 fetch
├─────────────────────────────────────────────┤
│  类型契约  types/index.ts                    │  ← Article / AuthUser 等
└─────────────────────────────────────────────┘
            │  fetch('/api/v1', credentials)  │
            ▼                                  ▼
        Express + MongoDB  （代理同源，Cookie 登录态）
```

**一句话讲架构**：分层的核心是一条**防腐层（anti-corruption layer）**——`adapters.ts`
把后端 DTO 翻译成组件用的 `Article`，后端改字段前端只动一个文件；`client.ts` 把
"HTTP 状态码 + 业务错误码 + 超时 + 取消"收敛成一个 Promise，页面里永远只有
`try/catch`。

## 3. 六个关键决策

### 3.1 搜索：竞态取消 + 中文输入法 + URL 同步

- **难点**：搜索框每敲一字就发请求，慢请求后回来会覆盖快结果（竞态）；中文输入法组合期
  发请求会出乱码/多余请求；直接 push 路由会让后退键失灵。
- **做法**：
  - 防抖 300ms；`AbortController` 取消上一次请求，并做 **inflight 比对**（即使取消失败，
    也以"最新一次响应"为准，慢的不覆盖）。
  - `compositionstart/end` 期间**不发请求**；用 `lastQuery` 去重解决不同浏览器
    `compositionend` 与 `input` 触发顺序不一致导致的重复请求。
  - 用 `history.replaceState` 同步关键词到 URL，**不污染历史记录**。
  - 状态用四态枚举 `idle | searching | done | error`，而不是 `loading: boolean`——
    要能区分"还没搜"和"搜了但没结果"，这两句话对用户完全不同。
- **代价**：`replaceState` 意味着搜索页的浏览器前进/后退要靠路由自己处理，
  不能依赖浏览器的滚动恢复。

### 3.2 XSS 防护：Markdown 渲染的"顺序"陷阱

- **难点**：文章正文是 Markdown，渲染后 `v-html` 输出 = 存储型 XSS。
- **做法**：`DOMPurify.sanitize(markdownIt.render(content))` —— **先渲染后清洗**。
- **实测结论（推翻过直觉）**：很多人以为"反过来（先清洗再渲染）也行"，但用一篇讲 XSS
  的文章当输入时，先清洗会**静默损坏代码块**（把载荷改成无害文本，作者内容被篡改）。
  所以顺序不能反的真实理由不是"漏防"，而是"损坏内容"。
  详见配套手册第 20 章。

### 3.3 路由鉴权：守卫必须先等登录态

- **难点**：写作页要登录。守卫直接判 `!user` 会把**已登录但首次直输 URL** 的人踢去登录页
  （因为 `initAuth` 还没跑完，`status=idle`）。
- **做法**：`beforeEach` 里**先 `await initAuth()`** 再判断；后端不可达（`offline`）时
  **放行**而非踢登录，避免"登录也登不了"的死循环。
- **边界**：这个 bug 只在"直接输 URL"时出现，从首页点链接进来不复现 —— 最容易漏测的一种。

### 3.4 防腐层 + 统一请求封装

- **防腐层**：`adapters.ts` 隔离 DTO 与视图模型；`Article` 类型里没有 `publishedAt`/`views`
  等后端字段，组件零耦合。
- **统一请求**：统一响应包 `{ code, message, data }`，业务码（40101/40301/40001）与 HTTP 码
  分离；**主动取消(-2) 和 超时(-1) 分开处理**——否则搜索会闪"网络连接失败"；带
  `credentials` 让 httpOnly Cookie 登录态生效。
- **为什么值得多写一层**：后端换了字段名，要改的是 `adapters.ts` 一个文件加一次单测，
  而不是全仓库搜字符串。

### 3.5 权限模型：软判断 + 硬拦截

- **做法**：前端 `isAuthor`（用户角色 + `article.author.id` 比对）只决定按钮显不显示；
  真正的拦截在后端 `requireRole('author')` + service 比对作者。
- **为什么**：前端显隐只是体验，越权防护必须后端兜底（别人拼 URL 直接发 DELETE 也被 403）。

### 3.6 本地草稿：不动后端模型的设计取舍

- **难点**：写作页刷新/误关要能恢复，但加"草稿状态"要同步改列表过滤、归档、权限，
  牵一发动全身。
- **做法**：草稿只存 `localStorage`，**不引入后端 `status` 字段**。
- **代价**：换设备就丢。界面文案必须说清这条边界，而不是假装它是云端草稿。

### 3.7 接口不可达时降级到本地演示数据

- **做法**：接口失败时回退到 `src/data/articles.ts` 的静态数据，页面**不白屏**。
- **边界**：不标注"这是演示数据"。这是**有意的选择**：对演示站点这是完整的表现，对真实产品
  则必须标注。详见配套手册第 23 章。

## 4. 已知短板与改法

| 短板 | 现状 | 改法 |
|---|---|---|
| 没用 Pinia | 只有"当前用户"一份跨页状态，模块级 `reactive` 单例够用 | 跨页状态到十几个时该上 Pinia |
| 无 ESLint | 只有 Prettier | 接 husky + lint-staged + CI |
| SPA 无 SSR，SEO 弱 | 杂志博客本该重视 SEO | 换 Nuxt/Vue SSR 或预渲染 |
| 色值硬编码 | 大量任意值（如 `#8B5A2B`） | 抽 design tokens |
| 无障碍(a11y) 弱 | 基本没做 | 补 `alt`/`aria`/键盘可达 |
| 组件测试偏薄 | 只有 `adapters` + `validators` 共 20 项纯函数单测 | 组件测试 / E2E 落进 CI |

## 5. 一些具体的坑（现象 → 成因 → 规避）

- **FormData 不能手动设 `Content-Type`**：浏览器的 multipart boundary 只有浏览器知道，
  手写成 `application/json` 会让 multer 报 `Multipart: Boundary not found`。
- **`client.ts` 的 signal 被覆盖**：`signal: timeoutController.signal` 会盖掉调用方传入的
  signal，表现为"传了取消但完全不生效"且不报错。解法是把外部 signal 摘出来单独转发。
- **超限上传在磁盘留下半截 `.tmp` 文件**：multer 先写盘后校验，校验失败时文件已经落盘。
  要在 filename 回调里自己记路径、在错误回调里删。
- **Tailwind preflight 把 `ul/ol` 的 `list-style` 重置为 `none`**：预览页和详情页样式不一致，
  预览里的列表变成没有圆点的缩进文字。**预览的唯一价值是所见即所得，不一致比没有预览更糟。**
- **SPA 返回首页丢滚动位置**：根因不是 `scrollBehavior`，是"列表未缓存 + 异步渲染"——
  组件重挂载时 DOM 还没渲染出来，页面高度不够就被夹到顶部。修法是模块级缓存首页数据。

## 6. 验证方式

| 手段 | 覆盖 |
|---|---|
| `vue-tsc --noEmit` | 类型契约（strict） |
| Vitest 单测（20 项） | 防腐层不泄漏后端字段、author.id 透传、表单校验 |
| 后端接口验收（61 项断言） | 文章/专栏/搜索/鉴权/上传/越权 |
| 文案审计脚本 | 用户可见文案 0 条英文残留、前后端空值文案一致性 |
| Playwright 端到端 | 注册→写稿→传封面→预览→发布→改稿→草稿恢复→越权拦截 |
| CI | 每次 push 跑类型检查 + 单测 + 构建 |
